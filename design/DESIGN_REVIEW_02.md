## 0. 총평

v0.2에서 가장 잘된 것은 **C2를 (a)+(b)로 푼 결정**이다. 리뷰 #01은 "세션을 paused로 바꾸라"고만 했는데, 그러면 기준 화면 S7에서 running lane과 그 위의 취소 버튼·실행 중 활동 피드·"실행 중 → 큐잉" 칩이 전부 사라진다. 원본을 task 예산 초과(lane 하나만 멈춤)로 두고 세션 예산 초과를 S7-P 변형으로 분리한 결과, 두 화면이 나란히 "task 예산"과 "세션 예산"의 차이를 설명한다. 리뷰안보다 낫다.

배지 글리프도 의도대로 들어갔다. Badge 컴포넌트에 `Glyph` 텍스트 슬롯이 생겼고 60개 인스턴스가 라벨에 맞는 글리프를 달았으며, `paused`는 테두리(soft), `failed`·`offline`은 채움(solid)으로 스타일이 갈렸다. S7-P 헤더의 `⏸ paused · 예산`과 lane 카드의 `✕ failed`를 나란히 보면 색을 빼도 구분된다. `-text` 변형 3종과 `$ink-3` 상향(#71717A)도 확인했다.

문제는 **새로 그린 것의 마감**이다. task 이력 표는 5열을 232px에 욱여넣어 트리거 열이 11~30px가 됐고, S7-P는 S7을 복사한 뒤 헤더·우열·lane 카드만 고치고 참여자 칩·작성창·타임라인 메타는 그대로 두었다. 그리고 리뷰 #01 C1을 고치면서 "에이전트 상태는 lane을 집계하지 않는다"를 PRD에 넣었는데, 그 문장이 기존 FR-5.2와 부딪힌다는 것을 아무도 확인하지 않았다.

## 2. PRD·SCREEN 대조 — 새로 확인한 것

### 2.1 정확히 반영된 것 (v0.2에서 새로 확인)

- S7-P의 "진행 중이던 lane 2개의 턴이 취소되어 paused" = PRD FR-2.3 "예산·시간 초과는 취소". 세션 상태 `paused`, lane 상태 `paused`, task는 `paused(budget)` — 세 층이 PRD §7 열거값과 맞는다.
- S7-P 배너 "승인하면 같은 workdir·런타임 세션으로 재개" = FR-7.3 "같은 재개 경로(런타임 resume 우선, 같은 workdir)".
- S7-D deputy 시점: 취소 즉시·승인 22:31부터 = FR-3.4 t-3·FR-5.4 M7. HITL 발행 10:31 + 24h 기한의 절반 = 22:31로 계산이 맞는다.
- S6-7 "승인(approval)은 autonomy와 무관하게 절대 자동으로 나지 않습니다" = FR-5.4. 이 문장이 없으면 `autonomous`를 "승인도 자동"으로 오해한다.
- S6-3 Studio Mac 비활성 사유 "유예 7일 초과 · 묶인 세션 1개 일시정지" = FR-9.2.
- S8 `session_paused` 항목의 부가 설명과 `mention` "(트리거 아님)" = FR-3.3 규칙 3.
- S9 각주 "에이전트 하나가 lane을 여럿 가진다" = FR-6.1.

### 2.2 PRD와 어긋나거나 PRD가 모순되는 것

#### C1′. FR-1.3(집계 안 함)과 FR-5.2(`waiting_human` 전파)가 충돌하고, S7 @Lead 칩이 그 사이에 있다

**문제.** v0.2에서 PRD FR-1.3에 추가한 문장: "에이전트 상태는 lane 상태(`blocked`·`paused`)를 집계하지 않는다 … lane이 멈춘 에이전트의 상태는 `idle`이다." 그런데 기존 FR-5.2: "task는 `waiting_human`, **에이전트 상태도 `waiting_human`**." `waiting_human`은 FR-1.3의 6종에 들어 있으므로 이것은 task 상태를 에이전트로 올리는 규칙이다. 에이전트가 lane을 여럿 가지면 `waiting_human`도 `blocked`와 똑같이 "어느 lane?"이라는 문제가 생긴다. FR-1.3 추가 문장의 논리("에이전트 하나가 lane을 여럿 가지므로 그 값은 에이전트 층에서 정의되지 않는다")를 그대로 적용하면 `waiting_human`도 에이전트 상태에서 빠져야 한다.

**화면에서.** S7 lane 보드에 `@Lead · waiting_human · 스펙 확정 · Director 승인 대기` 카드가 있는데, 참여자 칩의 @Lead는 `idle`이다. FR-5.2대로면 `waiting_human`이어야 하고, FR-1.3 추가 문장대로면 `idle`이 맞다. 캔버스는 후자를 골랐지만 PRD가 둘 다 말한다.

**권고.** PRD가 정해야 한다. 두 가지 중 하나:
- (a) **에이전트 상태를 파생값으로 정의한다.** "running task가 하나라도 있으면 `working`, 아니면 `waiting_human` task가 있으면 `waiting_human`, 아니면 `idle`." `blocked`·`paused`는 파생에 넣지 않는다(그 lane의 프로세스는 끝났고 사람·에이전트의 답을 기다리는 것은 `idle`과 구분할 이유가 약하다). 이 경우 S7 @Lead는 `waiting_human`.
- (b) **`waiting_human`을 에이전트 상태에서 뺀다.** FR-1.3을 5종으로 줄이고 FR-5.2의 "에이전트 상태도"를 삭제. 이 경우 캔버스는 지금 그대로.

(a)를 권한다. "이 에이전트가 사람을 기다리고 있다"는 인박스와 짝이 맞는 정보이고, 파생 규칙 한 줄이면 FR-1.3·FR-5.2가 모두 성립한다. PRD v0.10 항목.

#### C2′. task 예산 초과의 "승인"이 무엇을 바꾸는지 PRD에 없다

S7 HITL 버튼 "계속 진행 승인 (task 예산 $4로 상향)". `budget_per_task`는 **에이전트 필드**(FR-1.1)다. 이 승인이 (a) Frontend 에이전트의 `budget_per_task`를 $4로 영구 변경하는가, (b) 이 task에만 1회 상향인가? FR-7.3은 "Director가 예산을 늘려 승인하면"까지만 말한다. 화면은 (b)처럼 읽히는데 스키마에 task별 예산 오버라이드 필드가 없다. PRD에 한 줄 필요 — 권고는 (b) + `task.budget_override`.

#### C3′. 세션 `paused` 중 `queued` lane의 처리가 PRD에 없다 (개발 에이전트 Q2)

S7-P 비용 각주 "승인 전까지 새 task는 dispatch되지 않음"은 합리적이지만 PRD FR-2.3·FR-7.3 어디에도 없다. `queued` lane이 `paused` 세션에서 dispatch되면 예산을 더 쓰므로 막는 것이 맞다. PRD FR-2.3에 "세션이 `paused`인 동안 `queued` task는 dispatch되지 않는다. 재개 시 순서대로 dispatch"를 추가한다. 캔버스(S7-P의 QA queued 카드 유지)는 이 규칙과 일치한다.

#### C4′. 마법사 단계 순서를 바꿔야 한다 (개발 에이전트 Q4)

S6-3 "자동 선택" 옵션 아래 주의문: "격리를 worktree로 고르면 5단계에서 저장소가 있는 머신을 다시 골라야 합니다 — 자동 선택은 none 격리에서만 유효." 이 문장이 존재한다는 것 자체가 순서가 틀렸다는 증거다. 런타임(3단계)의 유효한 선택지가 격리(5단계)에 의존하는데 격리를 나중에 고른다.

**권고.** 순서를 **goal → Director → 격리 → 런타임 → 참여자 → 종료 조건 → 한도**로 바꾼다. 근거:
- 격리가 런타임 후보를 제한한다(worktree → 저장소 있는 머신만, FR-2.1).
- 런타임이 참여자 프로파일 후보를 제한한다(`runtime_kind` 없는 프로파일 경고, SCREEN §4.4 4단계).
- 따라서 의존 순서는 격리 → 런타임 → 참여자다. 현재 순서는 런타임과 격리만 뒤집혀 있다.

바꾸면 S6-3의 주의문과 "5단계에서 다시 골라야" 되돌림 로직이 사라진다. PRD §6 Sessions 행과 SCREEN §4.4 표를 함께 고친다. 요약 패널 순서도 따라간다.

## 3. 새로 드러난 결함

### N1. S7 task 이력 표가 읽을 수 없다 (S7, S7-D 동일)

**증상.** 트리거 열("Lead 위임 10:03", "QA 스레드 답글 10:35")이 **글자 하나씩 세로로** 떨어진다. 렌더에서 "Le / ad / 위 / 임 / 10 / :0 / 3"으로 보인다.

**원인.** 표 행(`TR`)이 232px 안에 5열을 `horizontal`로 놓았고, 순번 60 + 상태·실행·비용이 `auto` 너비를 먼저 차지한 뒤 `fill_container`인 트리거 열에 **11~30px**만 남는다. `fixed-width` 텍스트가 그 폭에서 줄바꿈된다.

**수정.** 좌열 268px에 5열 표는 들어가지 않는다. **행을 2줄로** 바꾼다: 1줄 "#2 재지시 · cancelled · $0.18"(순번·상태·비용, 굵기로 구분), 2줄 "Alex 중단·재지시 10:12 · resume ✓"(트리거·실행). 각 줄은 `fixed-width` + `fill_container` 하나. SCREEN §4.5의 5열 정의는 "정보 5종"으로 읽고, 열 배치는 화면 폭에 맞춘다고 SCREEN에 한 줄 적는다.

### N2. 참여자 칩이 좌열을 넘친다 (S7·S7-P·S7-D)

@Frontend "engineer · Hermes · idle — lane #3 예산 대기"(279px), @QA(304px)가 268px 열을 넘어 "대기"가 잘린다. C1 부가 텍스트를 넣으면서 생겼다. 부가 텍스트를 **둘째 줄**로 내리거나(칩 Text 프레임이 이미 vertical), "lane #3 ⏸"처럼 줄인다. Agent Chip 컴포넌트의 Role 텍스트를 `fixed-width` + `fill_container`로 바꾸면 인스턴스 전부에 반영된다.

### N3. S7-P 복사 잔재 3건

S7을 복사해 만들면서 고치지 않은 곳이다. 세션이 멈췄다는 화면인데 아래 셋이 "돌아가는 중"이라고 말한다.

| 작성창 트리거 칩 | "@Backend · 실행 중 → 큐잉" | 실행 중이 아니다 | "@Backend · 세션 일시정지 → 큐잉" |
| 타임라인 @Lead answer 메타 | "10:31 · Backend #3 · Frontend #3 때문에 발행 · source: system" | HITL 카드의 메타가 Lead의 답글에 붙었다. 답글은 10:21이고 시스템 발행이 아니다 | "10:21 · 답글 → lane #2" (S7과 동일) |

### N4. 인박스 심각도 배지의 글리프가 구분되지 않는다 (개발 에이전트 Q1)

`action_required`와 `attention`이 **둘 다 "!"** 다. SCREEN §5는 "글리프가 1차 신호, 색은 보조"라고 했으므로 두 심각도는 글리프로 갈려야 한다. 권고: `action_required` **!** (내가 해야 함), `attention` **▲** (알아야 함), `info` **i**. 인박스 뱃지가 action_required만 세는 규칙(SCREEN §4.6)과도 시각적으로 맞아떨어진다.

나머지 매핑은 적절하다: Kind 배지 `system ·`, `answer ↳`, `질문 ?`, `HITL ⏳`. `HITL·approval`에 ⏳(사람 대기)을 쓴 것은 HITL의 의미와 일치하므로 유지. `cancelled –`도 좋다. 다만 S10의 `기본` 배지가 ●(running 글리프)를 쓴다 — 상태가 아니므로 ★ 또는 글리프 없음.

### N5. `idle`의 색이 `done`이다 (S7 칩, S9 카드)

`idle` 배지는 글리프 ○(queued와 같음)에 색은 `$s-done`(초록)이다. 후속 조치 문서는 "queued/idle ○"이라 했는데 queued는 `$ink-3`(회색), idle은 초록이라 같은 글리프가 두 색이다. `idle`은 "끝"이 아니라 "할 일 없음"이므로 회색이 맞다. Agent Chip의 상태 점도 `$s-done`을 쓰고 있어 같은 문제다. 범례에 `idle`이 아예 없으니 추가한다.

### N6. 좌열 스크롤과 각주 클리핑

S7 3종 모두 lane 보드가 1073px로 열 높이 836px를 넘고, 그 아래 각주("칩 상태는 FR-1.3 6종만 …")가 **완전히 잘려** 보이지 않는다. 후속 조치 §2가 "의도된 스크롤"이라 했지만 각주는 스크롤 끝에서만 보인다. 각주를 참여자 아래(lane 보드 위)로 올리거나, lane 보드를 상태별로 접어 7장을 4장으로 줄인다. S8도 항목 8개가 900px를 넘어 정렬 각주가 잘렸다.
