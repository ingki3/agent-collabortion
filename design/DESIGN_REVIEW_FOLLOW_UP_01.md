### 2.1 S6 변형 렌더 (재확인 완료)

상위 프레임(`QdK3U`) 스크린샷은 세 번 재렌더해도 스텝 패널이 비어 보였다. 그러나 **스텝 패널 노드(`QFN1d`)를 직접 찍으니 정상 렌더**됐다 — 제목, 한도 4필드, Hermes 추정치 주의, autonomy 라디오 3개(guided 선택 · autonomous · supervised 비활성 + v1.1 배지), "승인은 자동 진행되지 않음" 각주, 이전/세션 만들기 버튼 전부 있다. 노드 데이터도 원본 S6과 구조가 동일함을 확인했다(`fill`·`fontSize`·`textGrowth` 일치).

**결론: 캔버스 데이터는 정상이고, `Copy`로 만든 최상위 프레임의 스크린샷 캐시가 갱신되지 않는 도구 특성이다.** 앱에서 직접 보면 정상이다. 다음 리뷰어는 최상위 프레임이 비어 보이면 자식 노드로 확인하면 된다.

S5·S9도 이번에 스크린샷으로 확인했다 — S5 3행 `paused · 런타임 오프라인` 배지가 잘리지 않고 soft 스타일(테두리)로, S9 Researcher `offline`이 solid(채움)로, QA·Frontend가 `idle`로 렌더된다.

## 3. 리뷰 원안과 다르게 처리한 것

**C2 — (b)만 하지 않고 (a)+(b).** 리뷰는 "세션을 `paused · 예산`으로 바꾸고 배너를 그리라"(b)를 권했다. 그러나 (b)만 적용하면 **원본 S7에서 running lane이 사라진다** — PRD FR-2.3에 따라 세션 예산 초과는 진행 중 턴을 취소하므로 Backend·Frontend 둘 다 `paused`가 되고, "중단하고 다시 지시 / 중단" 버튼, 활동 피드의 실행 중 상태, 트리거 미리보기의 "실행 중 → 큐잉" 칩을 보여줄 카드가 없어진다. S7이 나머지 화면의 규칙을 정하는 기준 화면이라는 리뷰의 판단을 따르면, 기준 화면은 **active** 상태여야 한다.

그래서 원본 S7은 (a) **task 예산** 초과(`budget_per_task` $2.00 → $2.40, 세션은 $3.20/$20로 active)로 바꾸고, (b)는 **S7-P 변형**으로 따로 그렸다. S7-P가 리뷰가 원한 배너·재개 버튼·취소된 lane을 전부 담는다. 두 화면이 "task 예산 초과"와 "세션 예산 초과"의 차이(전자는 lane 하나만 멈춤, 후자는 세션 전체)를 나란히 보여주는 부수 효과도 있다.

**§7 색 변경 — 하지 않음.** 리뷰가 "글리프가 있으면 필요 없다"고 했으므로 `$s-pause`는 #DB2777 그대로 두었다. 글리프와 soft/solid 스타일로 구분한다.

**§6.3 `$ink-3` — #71717A.** 리뷰 권고값 그대로.

## 7. 다음 리뷰에서 봐 주었으면 하는 것

1. **Badge 글리프 자동 매핑의 예외** — 상태가 아닌 라벨(`HITL · approval`, `질문 → @Lead`, `system`, `answer`, 인박스 심각도)에 붙인 글리프가 적절한지. 규칙이 아니라 매핑 표이므로 리뷰 대상이다.
2. **S7-P의 lane 처리** — 세션 예산 초과 시 running lane이 전부 `paused`가 되는 것이 PRD FR-2.3의 "예산·시간 초과는 취소"와 맞는지. `queued` lane은 어떻게 되는지(S7-P에서는 그대로 `queued`로 두었다 — 재개 시 순서대로 dispatch).
3. **S7-D 툴팁 위치** — 헤더 버튼 아래 absolute 배치. 실제 호버 위치를 표현한 것이 아니라 "이런 문구"의 예시다.
4. **S6-3 자동 선택의 단계 순서 문제** — 런타임(3단계)이 격리(5단계)보다 먼저라, "자동 선택"이 worktree와 충돌하는 것을 5단계에서 되돌려 잡아야 한다. SCREEN §4.4의 순서 자체를 바꿀지(격리 → 런타임) 판단이 필요하다.
