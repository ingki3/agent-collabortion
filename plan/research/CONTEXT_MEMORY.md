## 1. 문제 (실측, 게임 제작 방 2026-09-27)
- 비용 약 $2,606. Lead task 60개·도구 호출 2,133회, 호출당 맥락 중앙 약 39만 토큰(cache_read).
- 예전 대화 다시 읽기(`room messages`)는 12회뿐 — 비용은 「검색이 없어서」가 아니다. 셸 1,351회(브라우저 테스트 300·미디어 244) — Lead 가 조정자가 아니라 직접 제작·검증.
- 가설(0단계에서 검증): 재개된 런타임 세션에 턴마다 최근 50 + 미션 메시지 전부(9만~12만 토큰)가 한 벌씩 더 쌓인다. 캐시 TTL(5분 가능성) 만료 뒤 깨어나면 세션 전체가 캐시 쓰기로 재청구.
- 결정·사실·현재 값이 긴 `detail`(79만 자)에 흩어져 있고, 최근 50개·현재 미션 밖은 기억이 없다.

## 2. 운영 원칙 (Director 확정 2026-09-28)
**운영 중 맥락 관리에 사람은 개입하지 않는다.** 서버 규칙과 에이전트가 전부 맡는다. 사람은 지시하고 결과를 본다(원장은 화면에서 읽기만). 측정용 채점도 에이전트가 한다.

## 3. 목표 구조 (3층 — 03 조사로 수정된 판)
1. **맥락 수명주기(서버·데몬 규칙)** — 재개는 조건부, 기본은 「새 세션 + 원장」(조건: 누적 크기·캐시 만료·정체·초과). 턴 프롬프트는 밀어 넣지 않고 끌어 읽게: 미션 메시지 전부 → 머리글 색인 + 최근 N, 나머지는 CLI 로(multica 방식). Lead 의 무거운 검증은 QA lane 으로 — 브리프 권고로 시작, 계측에서 안 줄면 역할 명령으로 막는다. lane 보고 규격(한 일 / 찾은 것 / 남은 것 + 결과 + 참조), 위임문 5칸(대상 / 바꿀 것 / 제약 / 소유 범위 / 완료 증거 — Orca).
2. **방·미션 상태 원장(에이전트가 씀)** — 사실(확실도 4단계)·결정·현재 값·담당·포기한 안·열린 질문·계획·진척·교훈. 300자 항목 + 출처 메시지 id + 유효기간 + 대체 관계. `colab memory note / supersede / retire`. 계획·진척·담당은 Lead 가. 교훈은 graphify 식(유용/막다른 길/정정 표시 → 2건 이상 채택 → 30일 반감기, LLM 없음). 턴 프롬프트가 원문 더미 대신 원장을 싣는다([1]~[5] 밖 — E12-11 유지). 3회 정체면 원장으로 새로 시작(Magentic-One). 「여기까지 정리」·결정 기록은 화면 하나, 행은 따로.
3. **회상 검색(보조, 조건부)** — 어휘 검색 먼저. 벡터(pgvector)는 문항 점수가 모자랄 때만, 임베딩 경로 결정은 그때.
