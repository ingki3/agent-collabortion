# 08 — Orca `orca search`(대화 색인) 조사 — 3단계(회상 검색) 선행 자료

작성 2026-10-06 · Director 요청("최근 Orca 가 적용한 대화 색인 기능 조사") · 별도 에이전트 실측(GitHub PR·실제 호스트 호출) · 적용 대상 `CONTEXT_MEMORY.md` 3단계(아직 안 만듦, 이 문서가 선행 입력)

## 1. 무엇인가 (실측 확인)

"AI Vault search" — 이 머신의 모든 코딩 에이전트 툴(Claude Code·Codex·Cursor·Gemini·Hermes·Antigravity) 세션 로그를 **SQLite FTS5** 로 색인한 전체 텍스트 검색. 각 툴의 로그 파일(JSONL)을 tail 로 따라가며(파일별 바이트 오프셋 커서) 증분 색인하고, 별도 주기적 전수 재조정(sweep)이 놓친 파일·회전된 파일을 다시 잡는다. **기본 꺼짐**(설정에서 opt-in). 이 호스트에서 메시지 297,210건 색인됨.

GitHub `stablyai/orca` PR #18112·#19687·#19750·#20514·#20580·#20727·이슈 #17422 가 유일한 1차 자료(공개 블로그·체인지로그 산문 없음).

## 2. 메커니즘 (직접 호출로 확인)

- **단위는 세션 하나**다 — 메시지 하나가 아니다. 결과마다 가장 점수 높은 스니펫 **하나**만 오고, 세션 안의 다른 일치 줄을 더 보려면 그 세션을 통째로 다시 열어야 한다(`resumeCommand`).
- **`--scope conversation` vs `all` 는 실제로 다른 색인**이다 — 같은 질의에 `conversation` 은 대화 역할(user/assistant) 스니펫만, `all`(기본) 은 명령·도구 출력 스니펫도 나왔다. 후처리 필터가 아니라 별도로 색인된 것으로 보인다.
- **질의 라우팅은 자동 단계적 폴백**이다(`--debug` 의 `plannerReport.route`): 구문 그대로(phrase) 먼저 → 안 되면 모든 단어 AND → 그래도 없으면 OR. 호출자가 고르지 않는다.
- **정렬**: `relevance`(기본, bm25 류 점수) vs `newest`(점수 무시, 최신순).
- **신선도**: 기본은 "빠르지만 살짝 묵을 수 있음", `--fresh` 는 재조정을 최대 5초 기다린 뒤 검색한다 — **이 장치는 Orca 가 자기가 안 쓰는 외부 로그 파일을 색인하기 때문에 필요한 것**(크래시 복구용 파일별 커서, 회전 감지).
- **한국어 토큰화(우리 백로그에 "미실측"으로 남아 있던 질문 — 지금 확인함)**: `위임받`(다른 단어, "위임" 어근 공유)은 **0건** — "위임"은 수십 건 나오는데도. 「위임됨」이 포함된 줄에서도 "위임됨" 은 안 걸리고 독립된 "위임" 만 걸린다. **형태소 분석·어간 추출 없음, 완전 일치만 — CJK 인식 토크나이저가 아니다**(unicode61 류, 한글 연속 구간을 통째로 한 토큰으로 본다).

## 3. Colab 에 적용할 것 — 3단계(회상 검색) 구체안

- **진짜 빈 공간을 메운다**: 지금 에이전트는 `colab room messages --thread <id>`(스레드 하나 직접 조회)만 있고, **키워드로 옛 메시지를 가로질러 찾을 길이 없다.** `colab room search <query>` 를 Postgres `tsvector`/GIN 로 신설 — CONTEXT_MEMORY.md 3단계("어휘 먼저")의 첫 구현으로 바로 쓴다.
- `--scope conversation|all` 분할, `relevance|newest` 정렬, 초과 매치 시 `truncated` 플래그는 그대로 베낀다(비용 거의 0, Orca 가 실측으로 검증한 구분).
- **세션 단위 그루핑은 베끼지 않는다.** 우리는 이미 메시지·스레드 단위로 조회하므로, `room search` 결과는 메시지 하나하나(message id·thread id·스니펫)로 내는 게 Orca 보다 더 맞는 단위다.
- **sweep/reconcile/degradedRoots/generation/`--fresh` 는 베끼지 않는다.** Orca 가 통제 못 하는 외부 JSONL 을 색인해서 필요한 장치다. 우리는 Postgres 에 직접 쓰므로 같은 트랜잭션 안에서 GIN 인덱스가 갱신된다 — 묵음 문제 자체가 없다.
- **여러 툴·여러 프로젝트 가로지르는 색인(`--agent`·`--path`)은 베끼지 않는다.** 우리는 단일 제품·단일 스키마다.
- **한국어 한계를 안고 간다**: Postgres `tsvector` 를 `simple` 설정으로 쓰면 Orca 와 **똑같은 한계**(형태소 변형에 약함)를 그대로 안는다. 어간·조사 변형에 걸리려면 FTS 단독이 아니라 **`pg_trgm`(트라이그램) 을 한국어 보강으로 같이 쓴다** — 이건 Orca 가 안 가진 부분이라 베끼는 게 아니라 우리가 더 보강하는 지점이다.
- **작게 베낄 것**: `--debug` 의 phrase→and→or 라우팅 노출. `room search` 가 빈 결과거나 잘렸을 때 어느 폴백 단계가 작동했는지 보여 주면(Postgres `websearch_to_tsquery` 가 이미 phrase→AND 비슷한 의미라 구현 비용이 작다) 운영·에이전트가 빈 결과를 스스로 진단할 수 있다.

## 4. 3단계 착수 시점

지금(2단계 머지 직후) 바로 시작할지, 2단계 실사용 측정을 먼저 본 뒤로 미룰지는 Director 결정 대기. CONTEXT_MEMORY.md 표의 3단계 조건("긴 꼬리 recall@5 ≥0.8")을 재는 문항 세트가 아직 없다 — 착수하면 그것부터.
