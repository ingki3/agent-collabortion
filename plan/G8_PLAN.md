## 1. 시작·정지의 정의 (시계 셋)

F1 은 "계정 없음 → 첫 세션이 completed" 다. 시계를 셋 남기고 **G8 판정은 T2−T1** 로 한다(PRD §11 첫 행의 정의 그대로 "데몬 설치 → 첫 세션 완료"). T0 는 참고.

| 시각 | 정의 | 어디서 읽나 |
|---|---|---|
| **T0** | 참가자가 가입 페이지(S2)를 처음 연 순간. 계정 없음 | 관찰자 시계 + 서버 `user.created_at`(가입 완료 시각과의 차이로 검산) |
| **T1 (시작)** | 참가자가 **설치 명령을 처음 본 순간** — S4-2 "컴퓨터 연결" 화면이 뜬 순간. 이 명령을 본 적이 없어야 한다(§3 자격) | 서버 `runtime_pairing.created_at`(S4-2 진입 = 페어링 토큰 발급) |
| **T2 (정지)** | 참가자의 **첫 세션이 `completed`** 가 된 순간 | 서버 `session.finished_at`(status=completed) |
| 보조 | S7 첫 카드(U1 13단계 = 세션 시작) 시각 | `session.created_at` — U1 의 정의와 대조용 |

- **첫 세션의 모양**: 온보딩이 이끄는 대로 — 팀 템플릿(리서치 팀), 마법사 기본값(격리 none · 종료 조건 `Writer 아티팩트 AND Director 승인`), goal 은 참가자가 한 줄 입력(예시 placeholder 그대로 써도 된다). 세션이 completed 가 되려면 Writer 의 HITL 질문에 답하고 완료 승인을 눌러야 한다 — 그것도 F1 의 일부다(PRD §4 A 6~8단계).
- **완료를 재는 이유**: U1 은 "세션이 돌기 시작" 까지(13단계)지만 PRD §11 은 "완료" 다. 완료까지 재야 HITL·승인 화면(S7 카드·인박스)까지 온보딩이 이끄는지 본다. 단 완료 시간에는 **모델 턴 시간**(Lead 위임·Researcher·Writer, 실측 3~8분)이 섞인다 — 표에 **대기 시간(세션 시작 → 첫 HITL 카드)** 을 따로 적어 사람 몫과 모델 몫을 가른다.
- **15분의 기준**: 중앙값(5명) < 15분, T2−T1. 개별 실패(15분 초과·중도 포기)는 §5 양식에 남기고 중앙값에는 그대로 넣는다(포기 = ∞ 로 센다).

## 3. 참가자 자격 (5명)

- 이 제품을 써 본 적 없고, 설치 명령·화면을 본 적 없다(개발 참여자·리뷰어 제외).
- 터미널에서 명령을 붙여넣어 실행할 수 있다(Claude Code 를 쓰는 사람이면 충분).
- 역할 섞기: 개발자 3 + 비개발자 2 를 권장(시나리오 A 는 비개발 흐름이다).
- 같은 사람이 두 번 재지 않는다(재실측도 새 5명 — §7).

## 4. 관찰자 규칙 (개입하지 않는다)

1. 관찰자는 시작 전에 §2 의 한 문장만 말하고 **이후 어떤 질문에도 답하지 않는다.** "모르겠어요" 에는 "생각하시는 대로 해 보세요" 만.
2. 화면을 가리키거나, 스크롤·클릭을 대신하거나, 명령을 읽어 주지 않는다.
3. 참가자가 **3분 이상 같은 화면에서 멈추면** §5 의 "막힌 지점" 한 줄을 적는다(개입은 여전히 없다). 10분 이상 멈추면 참가자가 포기를 선언할 때까지 기다린다.
4. 실측 중 서버·데몬 로그를 보지 않는다(참가자의 문제를 미리 알면 표정·말이 새어 나간다). 로그는 끝난 뒤에 본다.
5. 끝난 뒤 사후 질문 3개(EVAL_USER §측정: "Lead 가 언제 깨어났나요?" "답을 안 하면 어떻게 되나요?" "코드는 어디 있나요?"(개발자만)) 를 그대로 묻고 답을 적는다.

## 5. 막힌 지점 기록 양식

참가자마다 한 장. 3분 이상 멈춤·뒤로 가기·다른 곳 클릭·소리 내어 한 말은 전부 한 줄씩.

| 시각(mm:ss, T1 기준) | 화면(S번호) | 참가자가 무엇을 찾았나 / 무엇을 했나 | 이탈 신호(EVAL_USER U1) | 해소(스스로 / 포기) |
|---|---|---|---|---|
| 02:10 | S4-2 | 복사 버튼을 못 찾고 명령을 드래그로 복사 | — | 스스로 |
| 05:40 | S4-2 | 3분째 `대기 중` — 터미널 오류를 읽고 있음 | 4단계 3분 이상 대기 → 문제 해결 안내가 자동으로 펼쳐졌나: 예/아니오 | … |
| 09:00 | S7 | Writer 의 질문 카드를 보지 못하고 새로고침 | — | … |

이탈 신호 셋(EVAL_USER U1): ① 4단계 3분 이상 `대기 중` ② 5단계에서 "직접 만들기" 먼저 ③ 9~10단계 뒤로 가기. 발생 횟수를 §6 표의 열로 센다.

## 7. 실패 시 재실측 규칙 (달력)

- 중앙값 ≥ 15분 이거나 포기가 2명 이상이면 **실패**. 막힌 지점 표(§5)에서 가장 많이 걸린 화면을 고친다(온보딩 수정 PR, Lead 리뷰).
- **재실측도 달력이다**: 새 참가자 5명 × 다시. 같은 사람을 다시 재지 않는다. 고친 빌드가 배포된 뒤에만 시작한다.
- 12주 상한을 먹는 유일한 재시도(PLAN §6.2). 달력 12주 도달 시 G9 는 열리되 **G8 실측은 생략 불가** — 그때까지의 실측 결과로 판정한다.
- 한 번의 재실측에서도 실패하면 Director 판단(v1.1 로 온보딩 항목 이월 여부).
