## 1. 설계 원칙

PRD에서 직접 따라오는 제약이다. 화면을 그릴 때 이 다섯 가지가 계속 충돌 판정 기준이 된다.

1. **작업의 중심은 세션이다.** 워크스페이스에는 에이전트·런타임·세션이 있고, 사람이 실제로 시간을 보내는 곳은 세션 상세 하나다. 나머지 화면은 세션을 시작하거나(Agents·Runtimes·새 세션) 세션 밖에서 응답하기 위해(Inbox) 존재한다.
2. **파괴적 동작은 화면 조작으로만 한다.** 어떤 메시지도 진행 중인 턴을 취소하지 않는다(FR-3.4). 취소는 lane 카드의 버튼이고, 그래서 lane 보드는 장식이 아니라 **유일한 제어판**이다.
3. **침묵도 렌더한다.** 이벤트가 없는 것도 정보다(FR-7.2). 빈 목록·대기·응답 없음은 모두 명시적 상태로 그린다. 빈 화면을 그대로 두지 않는다(§7).
4. **권한은 숨기지 않고 비활성으로 보인다.** Director만 쓸 수 있는 버튼도 다른 멤버에게 보이되 비활성이고, 이유를 툴팁으로 말한다. 누가 결정권을 갖는지가 화면에서 읽혀야 한다.
5. **런타임 능력에 따라 화면이 강등된다.** 구조화 이벤트를 주지 않는 런타임에서는 활동 피드가 텍스트로 떨어진다(§8.2.6). 이때도 "이 런타임은 툴 단위 로그를 제공하지 않습니다"를 표시해 침묵과 구분한다.

## 2. 사용자 상태와 접근 권한

### 2.1 인증 상태

| 상태 | 접근 가능 | 진입 시 |
|---|---|---|
| **로그아웃** | 로그인, 회원가입, 초대 수락 | 보호된 URL 접근 시 로그인으로 보내되 **원래 URL을 기억**했다가 로그인 후 그 자리로 복귀 |
| **로그인, 워크스페이스 없음** | 워크스페이스 생성, 초대 대기 목록 | 온보딩(§4.2)으로 강제 이동 |
| **로그인, 워크스페이스 있음, 런타임 없음** | 전체 화면 접근 가능하나 세션 생성 불가 | Runtimes 화면의 "Add a computer"로 유도. 세션 생성 버튼은 비활성 + 이유 표시 |
| **로그인, 준비 완료** | 전체 | 마지막으로 본 세션 또는 Sessions 목록 |

세션 생성이 런타임을 요구하는 이유는 세션이 `runtime_id`에 묶이기 때문이다(FR-2.1, C4). 런타임이 하나도 없으면 세션을 만들 수 없다.

### 2.2 역할

역할은 **세 층**으로 나뉘고 서로 독립이다. 화면 권한을 판정할 때 셋을 각각 봐야 한다.

| 층 | 값 | 근거 |
|---|---|---|
| 워크스페이스 역할 | `owner` / `admin` / `member` | §7 `member.role` |
| 세션 역할 | `director` / `deputy` / `participant`(참여자) / `observer`(비참여 멤버) | FR-2.1 |
| 에이전트 소유 | 에이전트별 `owner_id` | FR-1.9 |

### 2.3 화면·동작별 권한 매트릭스

| 동작 | owner | admin | member | 비고 |
|---|---|---|---|---|
| 워크스페이스 설정 변경 | ✅ | ✅ | ❌ | 예산·루프 상한·보존 기한 |
| 멤버 초대·역할 변경 | ✅ | ✅ | ❌ | owner 강등은 owner만 |
| 런타임 추가·삭제 | ✅ | ✅ | ❌ | 활성 세션이 걸린 런타임은 삭제 차단(FR-9.2) |
| 에이전트 생성 | ✅ | ✅ | ✅ | 생성자가 `owner_id` |
| 에이전트 수정·삭제 | 소유자 또는 admin 이상 | | 소유자만 | FR-1.9 |
| 에이전트를 세션에 초대 | 에이전트의 `respond_to` 값이 정한다 | | | FR-1.9 |
| 세션 생성 | ✅ | ✅ | ✅ | 생성자가 기본 Director |
| **Director 교체** | ✅ | ✅ | 현재 Director만 | t-5 |

세션 내부 동작은 워크스페이스 역할이 아니라 **세션 역할**이 정한다.

| 세션 내 동작 | director | deputy | participant | observer | 근거 |
|---|---|---|---|---|---|
| 메시지 게시·멘션 | ✅ | ✅ | ✅ | ❌ | |
| HITL 응답(`question`·`choice`·`info`) | ✅ | 기한 절반 경과 후 | ❌ | ❌ | FR-5.4 |
| HITL 승인(`approval`) | ✅ | 기한 절반 경과 후 | ❌ | ❌ | 자동 진행 없음 |
| lane "중단하고 다시 지시" / "중단" | ✅ | **즉시** | ❌ | ❌ | FR-3.4, t-3 |
| 세션 일시정지·종료(`manual`) | ✅ | ❌ | ❌ | ❌ | |
| 예산 초과 후 계속 승인 | ✅ | 기한 절반 후 | ❌ | ❌ | FR-7.3 |
| 세션 열람 | ✅ | ✅ | ✅ | ✅ | 워크스페이스 멤버는 모두 열람 |

> **deputy의 비대칭**: 취소는 즉시, 승인은 기한 절반 이후다. 폭주를 멈추는 것은 지연될수록 손해가 커지고, 승인은 Director의 판단을 우선 기다려야 하기 때문이다(t-3). UI에서 승인 버튼이 비활성일 때 "Director 응답 대기 중 · 14:30부터 승인 가능"처럼 **언제부터 가능한지**를 함께 보여준다.

## 3. 화면 지도

### 3.1 전체 구조

```
[로그아웃]
  로그인 ──── 회원가입
     │           │
     └─→ 초대 수락 ─┐
                    ↓
[로그인]        온보딩 (워크스페이스 없음 / 런타임 없음일 때만)
                    ↓
        ┌───────────┴────────────────────────────────┐
        │            앱 셸 (좌측 내비 + 상단바)         │
        ├────────────────────────────────────────────┤
        │  Sessions ──→ 새 세션 마법사 ──→ Session 상세 │
        │      ↑                              │  ↑     │
        │      └──────────────────────────────┘  │     │
        │  Inbox ────────────────────────────────┘     │
        │  Agents ──→ Agent 편집 ──→ 테스트 채팅        │
        │  Runtimes ──→ Add a computer                 │
        │            └→ Workdir 관리                   │
        │  Settings (owner·admin)                      │
        └────────────────────────────────────────────┘
```

### 3.2 화면 목록과 우선순위

| # | 화면 | URL | v1 | 진입 경로 |
|---|---|---|---|---|
| S1 | 로그인 | `/login` | ✅ | 미인증 접근, 로그아웃 |
| S2 | 회원가입 | `/signup` | ✅ | 로그인 화면 |
| S3 | 초대 수락 | `/invite/:token` | ✅ | 이메일 링크 |
| S4 | 온보딩 | `/onboarding` | ✅ | 워크스페이스·런타임 없음 |
| S5 | **Sessions 목록** | `/sessions` | ✅ | 내비, 로그인 후 기본 |
| S6 | **새 세션 마법사** | `/sessions/new` | ✅ | Sessions, 빈 상태 CTA |

### 3.3 주요 사용자 흐름

**F1. 신규 사용자 → 첫 세션 완료** (목표: 15분, §11)
```
S2 회원가입 → S4 온보딩(워크스페이스 생성)
           → S12 Add a computer (설치 명령 2줄 복사 → 데몬 연결 대기)
           → S11 Runtimes (CLI 감지 확인)
           → S9/S10 에이전트 등록 (템플릿에서 팀 통째로)
           → S6 새 세션 마법사 → S7 Session 상세 (goal 자동 트리거)
```
가장 이탈이 많을 지점은 **S12의 데몬 연결 대기**다. 터미널에서 명령을 실행해야 하고 결과가 즉시 보이지 않는다. 연결될 때까지 폴링하며 "대기 중 → 연결됨 → CLI 3종 감지됨"을 단계로 보여준다.

**F2. HITL 응답** (지표: 중앙값 30분 내)
```
알림/뱃지 → S8 Inbox → 항목 선택 → 인라인 응답 (또는 S7로 이동해 맥락 확인 후 응답)
                                  → 응답 즉시 해당 task 재개, 항목은 목록에서 사라짐
```
Inbox에서 **맥락 없이 답할 수 있어야** 한다. 질문·선택지·에이전트의 제안 기본값·세션 goal 한 줄이 카드 안에 다 있어야 하고, 더 봐야 할 때만 세션으로 간다.

**F3. 방향 전환** (시나리오 C)
```
S7 → 메시지 작성 → 전송 (실행 중이면 큐잉, 턴은 죽지 않음)
   또는 lane 카드 → "중단하고 다시 지시" → 멘션 채워진 작성창 → 전송 → 턴 취소 후 재시작
   또는 lane 카드 → "중단" → 확인 → lane failed(cancelled)
```

**F4. 자식 에이전트의 질문** (FR-6.2.1)
```
Backend가 blocked → 서버가 질문 카드 게시 + 위임자(Lead) 즉시 깨움
                  → Lead가 질문 카드에 답글 → Backend lane 재진입
위임자 없는 lane이면 → S8 Inbox에 lane_blocked 항목 → Director가 답글
```

## 4. 화면별 상세 명세

### 4.1 S1~S3 인증

**S1 로그인** — 이메일/비밀번호 또는 SSO. 실패 시 사유를 구분해 표시(계정 없음 / 비밀번호 불일치 / 잠김). 보호된 URL에서 왔다면 로그인 후 그 URL로 복귀.

**S2 회원가입** — 이름·이메일·비밀번호. 가입 직후 S4 온보딩.

**S3 초대 수락** — 토큰으로 워크스페이스·초대자·부여될 역할을 미리 보여준다. 미로그인이면 로그인/가입 후 자동 수락. 만료·취소된 토큰은 사유를 명시하고 초대자에게 재요청하는 버튼을 준다.

### 4.2 S4 온보딩

목적은 **F1의 15분**을 만드는 것이다. 세 단계이며 각 단계는 건너뛸 수 있으나 건너뛴 것은 홈에 체크리스트로 남는다.

| 단계 | 내용 | 완료 판정 |
|---|---|---|
| 1. 워크스페이스 | 이름 입력 (팀원 초대는 나중에) | 생성됨 |
| 2. 컴퓨터 연결 | S12를 인라인으로 — 설치 명령 2줄, 연결 대기 | 데몬이 붙고 CLI 1종 이상 감지 |
| 3. 에이전트 | 팀 템플릿 선택(리서치 팀 / 개발 팀 / 콘텐츠 팀) 또는 직접 생성 | 에이전트 1개 이상 |

3단계에서 **템플릿을 전면에 둔다.** 에이전트를 하나씩 만들게 하면 15분을 못 맞춘다. 템플릿은 역할·instruction만 담고 프로파일은 감지된 런타임에 맞춰 자동 매핑한다(FR-1.4).

### 4.3 S5 Sessions 목록

**표시 정보** — 행마다: 상태 배지, 제목, goal 한 줄, Director 아바타, 참여 에이전트 아바타 묶음, 진행률(종료 조건 충족 수/전체), 누적 비용 및 예산 대비 %, 마지막 활동 시각, **주의 배지**(HITL 대기 N · blocked N · 실패 N).

**세션 상태 배지** (FR-2.3)

| 상태 | 표시 | 색 의미 |
|---|---|---|
| `draft` | 초안 | 중립 |
| `active` | 진행 중 (+ 실행 중 lane 수) | 진행 |
| `paused` | 일시정지 **+ 사유** (예산/시간/루프/런타임 오프라인/수동) | 주의 |
| `completing` | 마무리 중 | 진행 |
| `completed` | 완료 | 성공 |
| `cancelled` | 취소됨 | 중립 |

`paused`는 **사유를 배지에 함께** 쓴다. 원인마다 사용자가 할 일이 다르다 — 예산이면 승인, 런타임 오프라인이면 재바인딩(FR-9.2).

**기능** — 필터(상태·Director·참여 에이전트·런타임·기간), 정렬(최근 활동·비용·생성일), 검색(제목·goal), 새 세션 CTA.

**빈 상태** — 런타임이 없으면 "먼저 컴퓨터를 연결하세요"로 S12를 가리키고, 있으면 새 세션 CTA를 크게 놓는다.

### 4.4 S6 새 세션 마법사

PRD의 순서를 그대로 따른다: **goal → Director → 런타임 → 참여자·프로파일 → 격리 → 종료 조건 → 한도**. 각 단계는 되돌아갈 수 있고 마지막에 요약을 보여준다.

| 단계 | 입력 | 검증·주의 |
|---|---|---|
| 1 goal | 제목, goal(필수), 성공 기준 체크리스트(선택), 첨부 컨텍스트(문서·URL·파일·이전 세션) | 이전 세션 첨부 시 요약 토큰 상한을 표시(FR-4.4) |
| 2 Director | 워크스페이스 멤버 중 1인(기본 생성자), deputy(선택) | deputy는 승인 권한이 기한 절반 후 생김을 안내 |
| 3 **런타임** | 온라인 런타임 중 선택 | `worktree`·`container` 격리면 **필수**. 저장소 경로·remote URL·클린 여부를 데몬 probe로 검증해 표시(FR-9) |
| 4 참여자 | 에이전트 다중 선택 + 각자 프로파일 + assignee 지정 | 선택한 런타임에 없는 `runtime_kind`의 프로파일은 경고. `respond_to`로 초대 불가한 에이전트는 목록에서 사유와 함께 비활성 |
| 5 격리 | `worktree`(저장소 선택) / `none` — **v1은 2종**, `container`는 v1.1 | worktree 선택 시 workdir 바인딩 규칙(에이전트당 1개)을 그림으로 설명 |
| 6 종료 조건 | `artifact_submitted` / `agent_approval` / `user_approval` / `manual` 조합(AND·OR) | 기본값 `artifact_submitted(assignee) AND user_approval`. **`agent_approval` 단독이면 "사람 승인 없이 완료됩니다" 경고**(m-m) |
| 7 한도 | 예산(USD), 시간, 최대 task, 최대 병렬 lane | 초과는 완료가 아니라 `paused`임을 명시. 추정 비용만 주는 런타임이면 하드 컷을 하지 않음을 알림(FR-7.3) |

> **`criteria_met`은 v1 목록에 없다**(v1.1). 6단계 선택지는 네 개다.

### 4.5 S7 Session 상세 — 핵심 화면

3열 레이아웃. 좁은 화면에서는 좌·우 열이 접히고 탭으로 전환된다.

```
┌─ 좌 (참여자 + lane 보드) ─┬─ 중앙 (타임라인) ────────┬─ 우 (진행·산출물) ─┐
│ 참여자                     │ [메시지 타임라인]         │ Goal & 성공 기준     │
│  @Lead    idle             │  · 사람/에이전트 메시지   │ 종료 조건 진행률     │
│  @Backend working ●        │  · 스레드                 │  ✅ artifact 제출    │
│  @QA      blocked ?        │  · HITL 카드              │  ⬜ Director 승인    │
│                            │  · blocked 질문 카드      │                      │
│ Lane 보드                  │  · 시스템 메시지          │ 아티팩트 (v2)        │
│ ┌────────────────────────┐ │  · 활동 피드(펼침)        │  patch_v1.diff       │
│ │ queued   │ running   │ │ │                           │                      │
│ │ waiting  │ blocked   │ │ │ ───────────────────────── │ 결정 기록            │
│ │ done     │ failed    │ │ │ [작성창]                  │ 비용 $3.20 / $20     │
│ └────────────────────────┘ │  @멘션 · 새 lane 토글     │ 런타임: MacBook      │
└────────────────────────────┴───────────────────────────┴──────────────────────┘
```

#### 좌열 — 참여자와 lane 보드

**참여자**: 이름, 역할, 현재 상태 배지(`idle`/`working`/`waiting_human`/`error`/`offline`/`disabled` — FR-1.3), 사용 중 프로파일. `offline`과 `disabled`는 아이콘과 문구를 다르게 한다(원인이 다름).

**lane 보드**: lane 카드를 상태별로 묶어 보여준다. 카드에는 담당 에이전트, 위임 요약, 경과 시간, `reentry_count`(재진입했다면), workdir 참조가 들어간다.

| lane 상태 | 카드 표시 | 가능한 동작 |
|---|---|---|
| `queued` | 대기 순번 | — |
| `running` | 진행 시간, 현재 동작 한 줄 | **중단하고 다시 지시** / **중단** (director·deputy) |
| `waiting_human` | 어떤 HITL을 기다리는지 + Inbox 링크 | 응답하러 가기 |
| `blocked` | **질문 배지 + 질문 요약**, 누구의 답을 기다리는지 | 질문 카드로 이동 |
| `done` | 산출물 요약 | — |
| `failed` | 실패 분류(`budget_exceeded`·`timeout`·`runtime_offline`…) | 재시도 |

> `waiting_human`과 `blocked`는 **아이콘과 문구를 확실히 구분**한다. 전자는 사람을, 후자는 다른 에이전트를 기다린다(FR-6.2). 사용자가 "내가 뭘 해야 하나"를 즉시 판단할 수 있어야 한다.

#### 중앙 — 메시지 타임라인

메시지 종류(`message.kind`)마다 다른 카드로 렌더한다.

| kind | 카드 |
|---|---|
| `text` | 일반 메시지. 작성자 아바타, 멘션 하이라이트, 스레드 답글 수 |
| `hitl` | **HITL 카드** — 질문/선택지/승인 요청, 에이전트의 제안 기본값, 기한과 `overdue` 표시. 응답 버튼은 권한자에게만 활성 |
| `blocked_q` | **질문 카드** — 어느 lane의 누가 무엇을 묻는지. **이 카드가 답글의 스레드 루트**다(FR-6.2.1) |
| `system` | 시스템 메시지(합류 결과, 재진입 통보, Director 변경, 정책 강등 등). 시각적으로 낮은 대비 |
| `summary` | 세션 완료 요약 |

각 에이전트 메시지에는 **"활동 보기"** 펼침이 붙어 그 run의 활동 피드를 인라인으로 연다(FR-7.2).

**활동 피드** — 항목마다 한 문장: *에이전트가 [동사]를 [목적어]에 했다 → [결과]*. v1은 중추 5클래스 + 일반 툴 + 원본 레일을 렌더한다.

- 진행 중 항목은 **제자리에서 갱신**한다(대기 → 실행 중 → 완료/실패). 상태 줄을 쌓지 않는다.
- 실패는 크게, 조회는 조용하게.
- 침묵·유휴·타임아웃도 "대기 중…", "응답 없음"으로 렌더한다.
- 원본 레일 토글로 가공 없는 출력을 본다.
- 런타임이 구조화 이벤트를 주지 않으면 메시지 카드 + 원본 레일만 남기고 **그 사실을 명시**한다.

**작성창** — 멘션 자동완성(`@` 입력 시 참여자 목록), **트리거 미리보기**("이 메시지는 @Backend를 트리거합니다 · 실행 중이라 큐잉됩니다"), **"새 lane으로 보내기" 토글**(t-2, 켜면 전송 버튼 옆에 표시), 스레드 답글 시 대상 표시.

> 트리거 미리보기는 FR-3.3의 8개 규칙과 lane 해소 규칙의 결과를 **보내기 전에** 사람이 확인하는 장치다. 규칙이 복잡하므로 미리보기 없이는 예측 불가능하다.

#### 우열 — 진행 상황

goal과 성공 기준, **종료 조건 진행률**(조건별 충족 여부와 누가 충족시킬 차례인지), 아티팩트 목록(버전 포함), 결정 기록, **비용**(누적/예산, 추정치면 배지), 런타임과 격리 방식, 세션 설정 요약.

세션이 `paused`면 우열 최상단에 **사유와 해결 버튼**을 띄운다(예산 초과 → "계속 진행 승인", 런타임 오프라인 → "다른 런타임으로 재바인딩").

#### 상단 액션

세션 일시정지, 종료(`manual`), 설정 편집, Director 교체. 파괴적 동작은 확인 단계를 둔다.

### 4.6 S8 Inbox

**목적**: "지금 내가 답해야 할 것"을 세션을 열지 않고 처리한다. 정의는 "나에게 열려 있는 HITL 요청 + 기한이 임박한 항목"의 합집합(FR-5.4).

| 항목 타입 | 심각도 | 카드 내용 | 인라인 동작 |
|---|---|---|---|
| `hitl_request` | action_required | 세션·에이전트·질문/선택지/승인 대상, **제안 기본값**, 기한·`overdue` | 답변·선택·승인/거절 |
| `lane_blocked` | action_required | 위임자 없는 lane의 질문(FR-6.2.1) | 답글 작성 |
| `session_paused` | attention | 사유(예산/시간/루프/런타임) | 계속 승인 / 세션 열기 |
| `run_failed` | attention | 실패 분류·에이전트 | 재시도 / 세션 열기 |
| `runtime_offline` | attention | 머신·경과 시간, 7일 유예 잔여 | Runtimes 열기 / 재바인딩 |
| `session_completed` | info | 결과 요약 | 세션 열기 |
| `mention` | info | 나를 멘션한 메시지 | 세션 열기 |

**정렬**: `overdue` → action_required → attention → info, 각 묶음 내에서 기한 임박 순.
**필터**: 미읽음 / 액션 필요 / 세션별.
**뱃지**: 내비의 Inbox에 action_required 개수만 카운트한다. info까지 세면 뱃지가 무의미해진다.

### 4.7 S9 Agents 목록 · S10 Agent 편집

**S9** — 카드마다 이름·역할·역할 설명·상태·기본 프로파일(런타임+모델)·소유자·`respond_to` 값. 필터(역할·런타임·상태·소유자). 새 에이전트, **팀 템플릿**(FR-1.4).

> `.agent.md` 가져오기/내보내기와 Build with AI는 **v1.1**이다. v1의 S9에는 폼과 템플릿만 둔다.

**S10** — 3구역.

| 구역 | 내용 |
|---|---|
| 정체성 | 이름(멘션 라벨, 워크스페이스 내 유일), 역할 태그, **역할 설명**(다른 에이전트의 로스터에 노출되므로 위임 판단 근거가 된다고 안내), 아바타 |
| instruction | 시스템 프롬프트 편집기. `lead` 역할 선택 시 "코디네이션 프로토콜이 자동 추가됩니다"를 알림(§8.3) |
| 실행 | **프로파일 목록**(추가·삭제·기본 지정) — 각 프로파일은 런타임 종류 → 모델 → 옵션(effort 등) → env/args → 폴백 프로파일. 툴·MCP 허용 목록, `max_concurrent_tasks`, `budget_per_task`, `respond_to`(+ allowlist) |

프로파일 편집기에서 **모델 목록은 데몬 probe 결과**로 채운다(§8.2). 런타임 능력에 없는 옵션(effort 미지원 등)은 비활성 + 사유 표시(§8.2.6).

**테스트 채팅** — 세션을 만들지 않고 이 에이전트와 1:1로 시험 대화. 실행 경로(ACP/CLI)와 사용 토큰을 함께 보여줘 설정이 맞는지 확인시킨다.

**`respond_to: nobody`(킬 스위치)** 는 별도 위험 영역에 두고, 켤 때 "실행 중인 턴이 취소되고 대기 중 task가 취소됩니다. 열린 HITL은 남습니다"를 확인시킨다(FR-1.9).

### 4.8 S11 Runtimes · S12 Add a computer · S13 Workdir 관리

**S11** — 머신 카드: 이름·호스트·온라인 상태·마지막 접속·데몬 버전, **감지된 CLI 목록**(종류·버전·로그인 여부·모델 수), 실행 중 task 수, **workdir 사용량 합계**, 저장소 목록(경로·remote URL·브랜치·클린 여부 — FR-9). 오프라인이면 경과 시간과 **7일 유예 잔여**를 표시하고, 유예를 넘기면 "이 런타임에 묶인 세션 N개가 일시정지됨"과 재바인딩 링크를 띄운다(FR-9.2).

삭제는 활성 세션이 없을 때만 가능하고, 있으면 차단 사유와 대상 세션을 나열한다.

**S12** — 설치 명령 2줄(복사 버튼)과 **연결 대기 상태**. `대기 중 → 연결됨 → CLI 감지 중 → 준비 완료` 단계를 실시간으로 보여준다. 3분 이상 연결되지 않으면 문제 해결 안내(방화벽·권한·CLI 미설치)를 편다.

**S13** — workdir 목록: 종류(worktree/container/dir), 소유 에이전트 또는 lane, 경로·브랜치, 용량, 마지막 사용, **보존 만료일**, 상태(활성/보존 중). 수동 삭제 가능하되 **미병합 커밋이나 미커밋 변경이 있으면 경고하고 기본 차단**한다(FR-6.4 M4). 워크스페이스 용량 상한 대비 사용률을 상단에 표시한다.

### 4.9 S14 Settings

| 탭 | 내용 | 권한 |
|---|---|---|
| 멤버 | 목록·초대·역할 변경·제거 | owner·admin |
| 런타임 정책 | 데몬 동시 task 상한, 런타임별 상한 | owner·admin |
| 예산 | 워크스페이스·세션 기본 상한, 초과 시 동작 | owner·admin |
| 루프 상한 | `max_chain_depth`(8) · `max_hops_per_hour`(60) · `max_pair_roundtrips`(5) | owner·admin |
| 컨텍스트 | `context_reuse.max_summary_tokens`(2000) · 아티팩트 포함 여부 | owner·admin |
| Workdir | 기본 격리 방식, `workdir_retention_days`(14) · `workdir_disk_quota_gb` · `runtime_offline_grace`(7일) | owner·admin |

기본값은 모두 PRD의 값을 그대로 쓴다. 각 항목에 **바꿨을 때의 영향**을 한 줄로 적는다(예: 루프 상한을 낮추면 정상 위임이 막힐 수 있음).

## 5. 공통 컴포넌트

여러 화면에 반복되는 요소는 한 번만 정의한다.

| 컴포넌트 | 쓰이는 곳 | 규칙 |
|---|---|---|
| **에이전트 칩** | 참여자, lane 카드, 메시지, 로스터 | 아바타 + 이름 + 상태 점. 클릭 시 프로필 팝오버(역할 설명·프로파일·현재 작업) |
| **상태 배지** | 세션·lane·task·에이전트·런타임 | 상태별 색·아이콘을 **전 화면 통일**. 같은 단어가 다른 층에서 다른 뜻이면(예: `paused`) 층을 함께 표기 |
| **HITL 카드** | Inbox, 세션 타임라인 | 두 곳에서 **같은 컴포넌트**를 쓴다. 질문·선택지·제안 기본값·기한·권한 상태가 항상 함께 |
| **비용 표시** | 세션 목록·상세, 런타임, task | 누적/상한 + % + 추정 배지. 추정이면 반드시 배지 |
| **멘션 입력기** | 세션 작성창, 테스트 채팅 | 자동완성 → `mention://` 링크 삽입. 트리거 미리보기 연동 |
| **활동 피드 항목** | 세션 타임라인 | §4.5의 렌더 규칙. 클래스별 아이콘 고정 |
| **권한 비활성 버튼** | 전역 | 숨기지 않고 비활성 + 툴팁으로 사유와 조건("Director만 가능", "14:30부터 가능") |
| **확인 다이얼로그** | 파괴적 동작 | 무엇이 사라지는지 명시. 되돌릴 수 없으면 그렇다고 씀 |

## 6. 실시간 갱신

PRD가 WebSocket/SSE를 전제하므로(§8.1), 화면마다 무엇이 실시간인지 정한다.

| 화면 | 실시간 대상 |

### 8.2 화면 설계에서 새로 드러난 확인 필요 사항

PRD에 정의가 없어 화면을 그리려면 정해야 하는 것들이다. **UI 결정이 아니라 제품 결정**이므로 PRD에 반영이 필요할 수 있다.

| # | 질문 | 왜 화면에서 걸리나 | 잠정안 |
|---|---|---|---|
| Q1 | **비참여 멤버(observer)가 세션을 볼 수 있나** | S5 목록에 남의 세션을 보여줄지, S7 접근을 막을지가 갈린다. PRD는 "세션 참여 = 트리거 허용"(FR-1.9)만 정하고 열람은 말하지 않는다 | 워크스페이스 멤버는 **열람 가능**, 쓰기는 참여자만. 비공개 세션은 v1.1 |
| Q2 | **세션 삭제가 가능한가** | S5에 삭제 동작을 둘지 결정 필요. PRD 상태 머신에 `deleted`가 없다 | v1은 삭제 없음. `cancelled` 후 보관만 |
| Q3 | **에이전트 아카이브 후 과거 세션 표시** | `archived_at`은 스키마에 있으나 UI 규칙이 없다 | 과거 메시지의 칩은 유지하고 "보관됨" 표시. 신규 초대 목록에서 제외 |
| Q4 | **테스트 채팅이 세션인가** | S10의 테스트 채팅이 `session` 레코드를 만드는지, 별도인지 | 별도 경량 채널. 세션 목록에 나오지 않음 |
| Q5 | **알림 채널** | S14 알림 탭의 실제 수단(이메일/푸시/웹)이 PRD에 명시되지 않음 | v1은 웹 알림 + 이메일. 푸시는 v2 |
| Q6 | **모바일 대응 범위** | 3열 레이아웃의 축소 규칙이 필요 | v1은 데스크톱 우선, Inbox 응답만 모바일에서 동작 |

### 8.3 v1 범위에서 화면이 빠지는 항목
