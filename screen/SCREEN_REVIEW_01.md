## 0. 총평

화면 문서의 강점은 **PRD의 원칙을 화면 규칙으로 번역한 §1**이다. "어떤 메시지도 턴을 취소하지 않는다"를 "lane 보드가 유일한 제어판"으로, "침묵도 렌더한다"를 "빈 화면을 두지 않는다"로 옮긴 것은 PRD의 의도를 정확히 읽은 결과다. `waiting_human`과 `blocked`를 아이콘·문구로 확실히 구분하라는 지시(§4.5), Inbox에서 맥락 없이 답할 수 있어야 한다는 요구(F2), F1의 이탈 지점을 데몬 연결 대기로 짚은 것도 PRD의 FR-6.2·FR-5.4·§11 지표에서 직접 따라온다.

§8.2에 "UI 결정이 아니라 제품 결정"인 질문 6개를 따로 뽑은 것도 좋다. 화면 문서가 PRD를 대신 결정하지 않고 되돌려보낸다.

어긋난 곳은 두 종류다. 첫째, **PRD에 없는 개념을 화면 문서가 만들었는데 그것이 PRD 규칙과 충돌**한다. 세션의 사람 역할을 `participant`/`observer`로 나눈 것이 대표적이다. PRD FR-5.3은 Director가 아닌 멤버의 메시지도 라우팅한다고 하는데, 화면 문서는 `observer`가 게시할 수 없다고 한다. 둘째, **PRD v0.8에서 바뀐 것을 v0.7 기준으로 적었다.** 예산 초과를 `failed(budget_exceeded)`로 쓴 것이 그렇다. v0.8은 `paused(budget)`다.

## 2. PRD와 어긋나는 것 — 와이어프레임 전에 수정

### C1. 세션의 사람 역할 `participant`/`observer`가 FR-5.3과 충돌한다 (§2.2, §2.3)

**문제.** 화면 문서는 세션 역할을 `director` / `deputy` / `participant` / `observer` 넷으로 나누고, `observer`(비참여 멤버)는 메시지를 게시할 수 없다고 한다. 그런데 PRD는:

- FR-5.3: "**Director가 아닌 멤버의 메시지도 라우팅되지만**, HITL 응답과 승인은 Director만 가능하다." 즉 워크스페이스 멤버는 누구나 게시할 수 있다.
- PRD의 `participant`는 **에이전트**다(`session_participant.agent_id`, FR-1.5 "delegate의 대상은 세션 participants"). 사람 participant 개념은 PRD에 없다.

화면 문서가 사람 역할에 같은 단어를 쓰면 구현자가 두 개념을 섞는다. 그리고 `observer`의 게시 금지는 PRD가 허용한 것을 화면이 막는 것이다.

**권고.** 사람 역할은 `director` / `deputy` / `member` 셋으로 줄인다. `member`는 열람·게시·멘션 가능(FR-5.3), HITL·취소·종료는 불가. "비공개 세션"이 필요하면 Q1대로 v1.1이며, 그때 `observer`를 도입한다. `participant`라는 단어는 에이전트에만 쓴다.

### C2. 예산 초과를 `failed(budget_exceeded)`로 표시한다 (§4.5 lane 카드 표)

**문제.** lane 카드 `failed` 행의 실패 분류에 `budget_exceeded`가 있다. PRD v0.8 FR-7.3: "상태는 `failed`가 아니라 **`paused(budget)`** 다. 예산 초과는 오류가 아니라 정책이고, Director가 승인하면 같은 재개 경로로 이어간다." task 상태 열거(§7)에도 `paused`가 따로 있다. v0.7 이전의 서술이 남은 것이다.

**권고.** lane 카드에 예산 초과 상태를 별도로 그린다. 표시는 "예산 초과로 대기 중 · 계속 진행 승인 필요"이고 동작은 Inbox의 `session_paused` 항목과 같은 승인 버튼이다. 단, PRD의 lane 상태 열거에는 `paused`가 없다(§5-P5). 화면은 task 상태 `paused`를 lane 카드에 투영한다고 적고, PRD에 lane 상태 추가를 요청한다.

### C3. 세션 생성 폼에 `autonomy`가 없다 (§4.4)

**문제.** FR-2.1의 폼 필드에 `autonomy`(`supervised` / `guided` / `autonomous`)가 있고, 이 값이 **v1 동작을 바꾼다**: FR-5.2·FR-5.4에서 `question` HITL의 기한 만료 시 "(a) 계속 대기 (b) `proposed_default`로 진행"이 `autonomy`에 따라 갈린다. 화면 문서의 7단계 마법사에는 이 필드가 없다. `supervised`만 v1.1이고 나머지 둘은 v1이다.

**권고.** 2단계(Director) 또는 7단계(한도)에 `autonomy` 선택을 넣는다. v1은 `guided`(기본) / `autonomous` 둘만 활성, `supervised`는 비활성 + "v1.1" 표시(§1 원칙 4). 선택지 설명에 "질문 기한이 지나면 에이전트 제안값으로 진행합니다"처럼 **실제 차이**를 적는다.

### C4. HITL `choice`·`info`를 v1 화면에 넣었다 (§2.3, §4.6)

**문제.** §2.3 권한표는 "HITL 응답(`question`·`choice`·`info`)"을, §4.6 Inbox 카드는 "질문/선택지/승인 대상"과 "답변·선택·승인/거절"을 나열한다. PRD §10은 v1 HITL을 `question` / `approval` 둘로 한정하고 `choice` / `info`는 v1.1이다.

**권고.** v1 표기를 `question` / `approval`로 좁히고, `choice`·`info`는 "v1.1에서 같은 카드 컴포넌트에 선택지·첨부 입력이 추가된다"로 자리만 잡는다. §5 공통 컴포넌트의 HITL 카드 규칙에 "타입별 입력부는 교체 가능"을 적어두면 v1.1 때 카드를 다시 설계하지 않는다.

## 3. PRD에 있는데 화면이 없는 것

### O1. 런타임 재바인딩 흐름 (FR-9.2)

S11에 "재바인딩 링크", S7 `paused` 배너에 "다른 런타임으로 재바인딩" 버튼이 있지만 **그 다음 화면이 없다.** FR-9.2가 요구하는 것은:

- 대상 런타임 선택. `none`이면 아무 온라인 런타임, `worktree`면 **remote URL이 같은** 저장소를 가진 런타임만.
- `worktree`일 때 "완료된 lane의 코드도 유실되며, diff 아티팩트를 재적용해 복구합니다"라는 경고.
- 재바인딩 / 세션 종료(`cancelled`) 두 선택.

이건 다이얼로그 하나지만 데이터 유실을 다루므로 명세가 필요하다. S11 또는 S7 하위에 "재바인딩 다이얼로그"를 추가한다.

### O2. 세션 진행 중 참여자 추가 (FR-1.5, §8.3)

FR-1.5: "로스터에 없는 역할이 필요하면 에이전트는 `ask_human`으로 Director에게 참여자 추가를 요청한다." 이 HITL을 받은 Director가 **어디서** 에이전트를 추가하는지 화면 문서에 없다. S7 상단 액션은 일시정지·종료·설정 편집·Director 교체뿐이다. "설정 편집"에 포함된다면 그렇게 적고, 추가 시 `respond_to` 초대 권한 검사(FR-1.9)와 프로파일 선택이 마법사 4단계와 같은 UI임을 명시한다.

### O3. task 단위 이력 (FR-3.4 B, FR-7.1)

PRD v0.7~v0.8은 task 정체성을 세밀하게 정했다. 재지시는 새 task(`restarted_from_task_id`), 재시도는 `attempt` 증가, HITL 재개는 새 attempt, `paused(budget)`는 task 상태. 화면 문서는 lane 카드까지만 그리고 **task를 보는 곳이 없다.** `reentry_count`는 lane 카드에 있지만 "이 lane이 3번 재지시됐고 2번째는 예산으로 멈췄다"를 볼 수 없다. lane 카드 펼침에 task 목록(트리거·attempt·상태·비용)을 두거나, 활동 피드가 task 경계를 표시한다고 정한다. 관측 지표(§9 "task 실패 분류별 비율")도 이 뷰가 있어야 사용자가 확인한다.

### O4. 트리거 미리보기의 `suppress_agent_ids` (FR-3.6)

FR-3.6: "`suppress_agent_ids`로 개별 억제 가능." 미리보기에 "이 메시지는 @A, @B를 트리거합니다"까지만 있고, 특정 에이전트를 빼는 조작이 없다. 미리보기 칩마다 × 버튼을 둔다.

### O5. deputy 위임 알림 (FR-5.2)

"기한의 절반이 지나면 deputy에게 위임 알림." Inbox 항목 타입에 이것이 없다. `hitl_request` 항목이 기한 절반 시점에 deputy의 Inbox에도 나타난다고 적으면 된다. §2.3의 "14:30부터 승인 가능" 툴팁과 짝이 맞는다.

### O6. Director 일시정지 후 재개, 루프 상한 `paused` 해소 (FR-2.3, FR-3.5)

S7 상단 액션에 "일시정지"는 있는데 "재개"가 없다. 그리고 §4.5 우열의 `paused` 해결 버튼은 예산·런타임 오프라인 두 경우만 적었다. 루프 상한 초과(FR-3.5 "paused + Director에게 HITL 알림")는 어떻게 푸는지 없다. `paused` 사유 5종(§4.3) 각각의 해소 동작을 표로 정리한다.

## 5. 화면 설계가 드러낸 PRD 쪽 공백 — PRD에 되먹일 것

화면 문서 §8.2의 Q1~Q6과 별개로, 화면을 그리면 PRD 자체가 모순되거나 비어 있는 것이 보인다. 이것들은 **화면 문서가 아니라 PRD를 고쳐야** 한다.

| # | 공백 | 근거 | 권고 |
|---|---|---|---|
| P1 | **결정 기록이 v1인가 v1.1인가** | PRD §6 Session 상세 우열에 "결정 기록"이 있고 FR-4.2도 v1 서술인데, §10 v1.1 목록에 "결정 기록"이 있다. 화면 문서는 v1로 그렸다 | 기록(`colab decision record`, HITL 응답 저장)은 v1, **전용 UI**만 v1.1로 §10을 고친다. v1은 우열에 목록만 표시 |
| P2 | **테스트 채팅이 v1인가** | PRD §6 Agent 편집에 "테스트 채팅"이 있지만 §10 v1 목록에 없다. 화면 문서 Q4가 "세션인가"를 묻지만 그 전에 범위가 불명확 | §10에 명시. v1이면 Q4의 잠정안(별도 경량 채널)을 PRD가 채택 |
| P3 | **루프 상한이 로드맵에서 빠졌다** | FR-3.5는 v1 서술이고 화면 문서 S14에 있는데, §10 v1·v1.1 어디에도 "루프 상한"이 없다(v0.5에는 v1.1에 있었다) | §10 v1 라우팅 항목에 추가. 핑퐁 방지는 v1 필수다 |
| P4 | **컨텍스트 재사용 UI 범위** | §10 v1은 "컨텍스트 재사용 상한 설정", v1.1은 "세션 컨텍스트 재사용(UI)". 화면 문서 S6 1단계는 "이전 세션 첨부"를 v1으로 그렸다 | 첨부(FR-4.4 기본)가 v1인지 명시. 아니면 S6 1단계에서 이전 세션 옵션을 v1.1로 |
| P5 | **task `paused` 시 lane 상태** | task에는 `paused`가 있고 lane에는 없다. lane 보드가 무엇을 보여줄지 PRD가 정하지 않았다(C2) | lane 상태에 `paused` 추가, 또는 "lane은 running 유지 + 카드에 task 상태 배지"로 명시 |
| P6 | **§6 UX 표의 v1.1 잔재** | Agents 행에 "Build with AI", 격리에 "container"가 v1처럼 나열 | §6에 v1/v1.1 표기 |

## 7. 살려야 할 것

- §1 설계 원칙 5개. PRD 원칙을 화면 언어로 옮긴 방식이 정확하다. 특히 "lane 보드는 장식이 아니라 유일한 제어판".
- §1 원칙 4 "권한은 숨기지 않고 비활성으로 보인다" + §5 "14:30부터 가능" 툴팁. deputy 비대칭을 사용자가 이해하게 만드는 유일한 방법이다.
- §3.3 F1의 이탈 지점 분석과 S12의 4단계 연결 표시.
- §4.5 "`waiting_human`과 `blocked`는 아이콘과 문구를 확실히 구분한다" — PRD FR-6.2의 "답을 줄 수 있는 주체가 다르다"를 화면으로 정확히 옮겼다.
- §4.6 뱃지는 action_required만 센다.
- §8.3 컷 순서별 화면 영향. PRD의 컷 표에 화면 열이 생긴 셈이다.
- §9 다음 단계 4번 "상태 배지·색 체계를 디자인 토큰으로 먼저" — 다섯 층이 같은 어휘를 쓴다는 관찰이 맞다.
